# GovBD-MRA: Federal Contract Intelligence Platform 🏛️

GovBD-MRA (Market Research Analytics) is a sophisticated enterprise platform designed to revolutionize how government contractors discover, analyze, and track federal procurement opportunities. Built as part of the Kontratar ecosystem, MRA combines real-time data ingestion, AI-powered analytics, and intelligent search to provide contractors with actionable insights into government spending patterns, entity relationships, and award trends.

> "Transforming government procurement data into strategic business intelligence."

---

## 🎯 The Challenge We Solve

Government contractors face significant challenges in the federal marketplace:

- 📊 **Data Overload**: 2M+ entities, 100K+ awards annually across multiple sources (SAM.gov, USAspending.gov, FPDS)
- 🔍 **Complex Search**: Multi-dimensional queries across entities, awards, agencies, NAICS codes, PSC codes
- 📈 **Analytics Gap**: Difficulty identifying spending trends, agency patterns, and competitive landscapes
- 🤖 **Manual Research**: Time-consuming manual research and opportunity tracking
- 🔗 **Fragmented Data**: Entity data, award data, and historical relationships scattered across systems
- ⏰ **Time Sensitivity**: Missing critical opportunities due to delayed notifications
- 💼 **Team Collaboration**: Coordinating research across multiple team members and projects

**GovBD-MRA solves all of these** by providing an integrated, AI-powered platform that automates data aggregation, analysis, and insight generation.

- **Performance Monitoring**: Track API calls, processing times


```
│  └─────────────────────┬─────────────────────────────────┘  │
│                        │                                     │
```

```
│  │  query_intent_service.py                              │  │
│  │  - LLM-based intent classification                    │  │
```

## 🚀 Getting Started

### Prerequisites

- **Java 17**: For EntityData and AwardLoad services
- **Maven 3.8+**: Java build tool
- **Python 3.11+**: For MRA Backend
- **Node.js 20+**: For MRA Frontend (Bun recommended)
- **Docker & Docker Compose**: For containerized deployment
- **PostgreSQL 14+**: Database (or Docker container)
- **Elasticsearch 8.15**: Search engine (optional, for advanced search)
- **Qdrant**: Vector database (or ChromaDB as fallback)

### Local Development Setup

#### 1. Clone Repository

```bash
git clone https://github.com/kontratar/govbd-mra.git
cd GovBD-MRA
```

#### 2. Configure Environment

Create `.env` file in project root:

```bash
# Environment
ENVIRONMENT=dev

# Ports
ENTITY_PORT=8080
AWARD_PORT=8081
BACKEND_PORT=8000
FRONTEND_PORT=3000

# Database
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DB=mra_db
POSTGRES_USER=mra_user
POSTGRES_PASSWORD=your_password
POSTGRES_SSL_ENABLED=false
POSTGRES_CERT=us-east-1-bundle.pem

# Vector Database
VECTOR_DB_TYPE=qdrant
QDRANT_HOST=localhost
QDRANT_PORT=6333
QDRANT_PROTOCOL=http
QDRANT_API_KEY=

# LLM Configuration
LLM_PROVIDER=ollama
LLM_MODEL=gemma3:27b
OPENAI_API_KEY=
GEMINI_API_KEY=

# SAM.gov API Keys (10 keys for rotation)
SAM_API_KEY_1=your_key_1
SAM_API_KEY_2=your_key_2
# ... up to SAM_API_KEY_10

# USAspending.gov (usually no key required)
USASPENDING_API_BASE_URL=https://api.usaspending.gov

# Stripe (for subscriptions)
STRIPE_SECRET_KEY=sk_test_...
STRIPE_PUBLISHABLE_KEY=pk_test_...
STRIPE_WEBHOOK_SECRET=whsec_...

# Frontend
NEXT_PUBLIC_API_URL=http://localhost:8000
NEXT_PUBLIC_MODE=development
```

#### 3. Start Services with Docker Compose

```bash
# Build and start all services
docker-compose up --build

# Or start individual services
docker-compose up entitydata
docker-compose up awardload
docker-compose up backend
docker-compose up frontend
```

#### 4. Manual Service Startup (Development)

**EntityData Service**:
```bash
cd mra_entityData
./mvnw clean package
./mvnw spring-boot:run
# Service runs on http://localhost:8080
# Swagger UI: http://localhost:8080/swagger-ui.html
```

**AwardLoad Service**:
```bash
cd mra_awardload
./mvnw clean package
./mvnw spring-boot:run
# Service runs on http://localhost:8081
# Swagger UI: http://localhost:8081/swagger-ui.html
```

**MRA Backend**:
```bash
cd MRA_BACKEND
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
python main.py
# Service runs on http://localhost:8000
# API docs: http://localhost:8000/docs
```

**MRA Frontend**:
```bash
cd MRA_FRONTEND
bun install  # or npm install

# Service runs on http://localhost:3000
```

### Frontend API Integration

**Authentication Flow**:

```typescript
// Login
const response = await axios.post('/auth/login', {
  email: 'user@example.com',
  password: 'password123'
});
const { access_token, refresh_token } = response.data;

// Store tokens
Cookies.set('access_token', access_token);
Cookies.set('refresh_token', refresh_token);

// Use axios interceptor for auth
axios.interceptors.request.use((config) => {
  const token = Cookies.get('access_token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// Refresh token on 401
axios.interceptors.response.use(
  (response) => response,
  async (error) => {
    if (error.response?.status === 401) {
      const refreshToken = Cookies.get('refresh_token');
      const { data } = await axios.post('/auth/refresh', {
        refresh_token: refreshToken
      });
      Cookies.set('access_token', data.access_token);
      // Retry original request
      return axios(error.config);
    }
    return Promise.reject(error);
  }
);
```

4. Analyze spending trends by agency

3. View top agencies by spending
4. Drill down into agency details
5. View recent awards in that NAICS

3. Receive email notifications

## 🐛 Troubleshooting

### Common Issues

**Issue 1: EntityData service fails to start**
```
Error: Unable to connect to PostgreSQL

Solution:
1. Check PostgreSQL is running: docker ps | grep postgres
2. Verify connection settings in properties/${ENVIRONMENT}.application.properties
3. Test connection: psql -h localhost -U mra_user -d mra_db
4. Check firewall/network: telnet localhost 5432
```

**Issue 2: Chat responses are slow**
```
Solution:
1. Check LLM provider status (Ollama/OpenAI/Gemini)
2. For Ollama, ensure model is downloaded: ollama pull gemma3:27b
3. Check Qdrant is running: curl http://localhost:6333/health
4. Monitor backend logs: tail -f logs/mra-backend.log
5. Increase timeout in frontend API calls
```

**Issue 3: Vector search not working**
```
Error: Qdrant collection not found

Solution:
1. Check Qdrant service: curl http://localhost:6333/collections
2. Create collections manually:
   curl -X PUT "http://localhost:6333/collections/entities" \
     -H "Content-Type: application/json" \
     -d '{"vectors": {"size": 768, "distance": "Cosine"}}'
3. Re-run embedding generation: POST /entities/generate-embeddings
4. Verify embeddings exist: GET /entities/embeddings/count
```

**Issue 4: Frontend can't connect to backend**
```
Error: CORS policy: No 'Access-Control-Allow-Origin' header

Solution:
1. Check NEXT_PUBLIC_API_URL in .env matches backend URL
2. Verify backend CORS settings in main.py (allow_origins)
3. For development, use: allow_origins=["*"]
4. For production, specify exact frontend origin
5. Restart backend after changes
```

**Issue 5: SAM API rate limiting**
```
Error: 429 Too Many Requests from SAM.gov

Solution:
1. Check API key rotation is working: GET /entities/system-info
2. Verify all 10 API keys are valid
3. Reduce concurrent requests per key (currently 10/sec)
4. Increase delay between requests in EnhancedSamApiClient
5. Monitor rate limits in logs
```
